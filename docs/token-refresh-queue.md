# Token 刷新后台任务

Token 刷新管理中的全量刷新、已选刷新、补刷从未刷新、失败重试，以及定时维护，使用 SQLite 持久化队列。提交接口返回 202，页面每 3 秒读取任务状态；关闭页面不会中止任务。

- 后台调度器每 5 秒检查队列，即使关闭定时维护，也会执行手动提交的任务。
- 同一数据库最多一个活动任务，账号串行处理，沿用设置中的账号间隔。队列不需要 Redis。
- 队列只保存账号 ID 和结果，不复制凭据；执行时重新读取账号配置，已停用或删除的账号跳过。
- 新令牌、刷新日志和账号完成结果在同一数据库事务内提交。
- 停止会等待当前账号完成；“继续未完成”只将剩余账号加入新任务。
- 服务异常退出后，120 秒执行租约到期，其他进程可继续未完成的账号。执行期间每 30 秒续租。服务停机期间不执行任务。
- Microsoft 请求无法加入本地事务；如果进程在远端响应后、本地提交前终止，该在途账号可能重试，不能保证远端请求严格只执行一次。

按天数模式每天应用时区凌晨 2 点检查；Cron 模式在指定时段检查。两者均根据**各账号最近成功刷新时间**和设置中的周期筛选，从未成功刷新的启用账号也会入队。一个失败账号不会中止整批任务，失败可手动重试，或在下一次维护检查时重试。

任务面板显示当前/最近任务的已处理、成功、失败、跳过和未处理数量，保留最近 30 条结果；账号列表的历史状态统计与任务计数分开显示。旧 SSE 和同步接口保留兼容，新的后台任务不依赖 SSE。

部署后重启应用即可创建新增队列表并启动消费，无需手动修改现有账号数据。建议先使用少量账号验证代理和微软授权，再运行全量任务。验证成功不保证授权永久有效。

## 批量重新授权

在 Token 刷新管理中使用“批量重新授权”：勾选账号后点“重新授权已选”，或点“重新授权全部失败账号”（所有启用且当前刷新失败的 Outlook 账号，不局限于当前页面）。授权通道可沿用账号配置，或明确选择 Graph / IMAP。建议先选择少量账号确认密码和代理有效。

此功能复用纯 HTTP 的微软 OAuth 登录流程，需要账号中保存的邮箱密码，使用应用配置的 `OAUTH_CLIENT_ID` / `OAUTH_REDIRECT_URI`。每个账号全程固定使用自身或分组继承的主代理；不会在登录过程中切换出口。重新授权最低间隔为 5 秒。

新授权必须通过目标通道的访问令牌验证才会保存。失败时保留原授权；分组、标签、备注、密码、转发和代理设置不变。账号在执行中被修改、停用或删除时，不覆盖它的新状态。

需要验证码、MFA、额外同意或微软登录页面不兼容纯 HTTP 流程时，无法保证全自动完成。失败会记录到账号状态，后续账号继续执行。可以在失败列表点击“手动授权”，使用原来的浏览器授权/回调 URL 流程。不会绕过微软的额外验证。

登录会话接口（保留应用现有 CSRF 校验）：

```http
POST /api/accounts/reauthorization-jobs
Content-Type: application/json

{"scope":"selected","channel":"auto","account_ids":[1,2,3]}
```

`scope` 支持 `selected` / `failed`，`channel` 支持 `auto` / `graph` / `imap`。成功提交返回 202 和任务对象；已有活动任务返回 409。进度、停止、继续复用 `/api/accounts/refresh-jobs/latest` 和 `/api/accounts/refresh-jobs/<job_id>/stop`、`/resume`。接口不返回密码或令牌。

## HTTP 优先，浏览器接管网页交互

邮箱列表勾选多个账号后：

- **刷新 Token**：先用 HTTP 刷新；确认 `invalid_grant`、过期或撤销授权后，尝试 HTTP 重新授权。HTTP 无法处理登录页面或交互要求时，再启动 Chromium。网络超时和明确的密码错误不会触发浏览器重复登录。
- **自动授权（HTTP 优先）**：直接开始重新授权，同样先 HTTP，必要时才用 Chromium。
- 原来的手动重新授权弹窗增加“自动重新授权，无需粘贴回调”，同样使用 HTTP 优先策略。

Token 刷新管理中可选择 HTTP 优先、仅 HTTP、仅浏览器。后台浏览器会在隔离的临时上下文中填写账号密码，处理普通同意授权页面并捕获回调，通过 state 和 PKCE 校验后交换令牌。每个账号结束后关闭浏览器，不保存浏览器用户目录、Cookie 或截图。验证码、短信、MFA 等验证不能自动绕过，会记录为需人工处理并继续后续账号。

镜像内安装 Chromium，Python 依赖包含 Playwright。非 Docker 部署需安装 Chromium，并可通过 `OAUTH_BROWSER_EXECUTABLE` 指定可执行文件（默认 `/usr/bin/chromium`）。Chromium 不支持带认证的 SOCKS5 代理，此类账号会明确报错，应为其配置 HTTP 代理；不会悄悄改为直连。

接口额外参数：`engine: "auto"` 表示 HTTP 优先、浏览器回退；`"http"` 和 `"browser"` 显式选择单一引擎。`action: "repair"` 表示先刷新再修复过期授权，`"reauthorize"` 表示重新授权。省略 engine 保留旧 HTTP 行为；页面默认使用 auto。
